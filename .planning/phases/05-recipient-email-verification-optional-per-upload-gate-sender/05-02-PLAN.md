<phase_decisions>
- D-05-05: Recipient email cap = 10 per upload (keeps StoredMeta JSON small and caps Mailgun send volume/file). Export `MAX_RECIPIENT_EMAILS = 10`.
- D-05-06: `MAILGUN_SENDING_REGION` defaults to "us" (values us|eu). Missing/blank MAILGUN_API_KEY/DOMAIN/FROM → throw → the endpoint returns HTTP 500 + `console.error` (FAIL LOUD, RESEARCH Open Q2), never a silent no-op.
- D-05-07: request-code rate limit = 1 per 60s per (file id + IP) — this single window doubles as the resend cooldown (RESEARCH A1). verify-code = 5 per 60s per (file id + IP), mirroring the password limiter. Both env-tunable (`RATE_LIMIT_REQUEST_CODE_PER_MIN`, `RATE_LIMIT_VERIFY_CODE_PER_MIN`).
- D-05-08: [FLAG] Recipient emails are stored in plaintext (lowercased/trimmed) in StoredMeta — the server must be able to email them. Minimal-exposure mitigation: never returned to any client; membership-check only via request-code. This is the privacy tradeoff CONTEXT.md flagged; confirm acceptable for the otherwise-anonymous app.
- Email validation: simple non-catastrophic-backtracking check `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` + a length cap (e.g. ≤254), matching the hand-rolled `validateClientMeta` style — no validation library (project has none).
</phase_decisions>
