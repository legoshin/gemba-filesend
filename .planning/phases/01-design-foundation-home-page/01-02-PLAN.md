<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| icon-data.js → DOM (`dangerouslySetInnerHTML`) | The Icon wrapper injects each glyph's `body` string as raw SVG markup. `body` is static, emitter-generated path/geometry markup shipped in-repo; the `name` prop is only a lookup key into the map and never flows into the injected markup. No user-controlled or network data reaches the sink. The client-side-encryption boundary is untouched (no crypto/upload/download/API code changes). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Tampering / Injection | `dangerouslySetInnerHTML` in `src/components/icon.tsx` | accept | `body` strings are a static in-repo asset (`icon-data.js`), not user- or network-derived; `name` only indexes the map and can at most select an existing safe glyph or return null. Documented via the preserved emitter-controlled-markup comment. If a future phase feeds dynamic glyph names, re-evaluate. |
| T-01-02-SC | Tampering | package installs | n/a | No package-manager installs in this plan — `icon-data.js`/`Icon.d.ts` are copied from the in-repo `design-system/` folder, not fetched from a registry. |
</threat_model>
