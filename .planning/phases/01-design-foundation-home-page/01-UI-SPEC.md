## Spacing Scale

**Project deviation from GSD generic default (intentional, token-locked):** Gemba's own spacing scale (`design-system/tokens/spacing.css`) is the source of truth, not the generic 8-point default. It is *mostly* multiples of 4 with one documented 2px exception used only for micro-gaps (chip icon/label gap).

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 2px | Micro-gap exception — chip internal icon↔label gap only |
| `--space-2` | 4px | Icon gaps, tight inline padding, input label↔field gap |
| `--space-3` | 8px | Compact element spacing, button icon↔label gap, toggle label gap |
| `--space-4` | 12px | Input horizontal internal gap, small-button padding |
| `--space-5` | 16px | Default element spacing, input padding, card inner padding |
| `--space-6` | 24px | Section padding, default-button horizontal padding |
| `--space-7` | 32px | Layout gaps between major home-page blocks |
| `--space-8` | 40px | Page-level spacing, large section breaks |

Exceptions: `--space-1` (2px) is the only non-multiple-of-4 value and is reserved for the Chip's internal icon/label gap (`gap: 4` in the reference Chip is actually `--space-2`; treat `--space-1` as reserved for any future sub-4px hairline gap need — do not introduce other odd values).

### Radii (component shape — required alongside spacing)

| Token | Value | Usage |
|-------|-------|-------|
| `--radius-xs` | 4px | Subtle/disabled field states |
| `--radius-sm` | 8px | Inputs, square button variants |
| `--radius-md` | 12px | Inner sub-cards (e.g. feature-card icon tile) |
| `--radius-lg` | 16px | Card/chip-on-short surfaces (COMP-05 card recipe) |
| `--radius-xl` | 24px | Pill buttons (default/small, non-square ranks), hero blocks |
| `--radius-pill` | 999px | Toggle track, fully-pill badges |

### Borders & Shadows (guardrail — inset rings, not CSS `border`)

| Token | Value | Usage |
|-------|-------|-------|
| `--ring-border` | `inset 0 0 0 1px var(--gemba-border)` (#E8EAED) | Card/input hairline — realized as `box-shadow`, never `border` |
| `--ring-focus` | `inset 0 0 0 2px var(--gemba-ink-800)` | Focus state on inputs/buttons, replaces default shadcn focus ring on redesigned surfaces |
| `--shadow-card` / `--shadow-field` | `0 4px 16px rgba(95,105,133,.06)` | Card and input elevation — soft cool-grey, never black |
| `--shadow-popover` | `0 12px 32px rgba(40,51,73,.16)` | Dropdowns/menus only (not needed on home page itself) |

Card recipe (COMP-05, confirmed not discretionary — DESIGN-SYSTEM.md guardrail): `background: var(--surface-card)` (white) + `border-radius: var(--radius-lg)` (16px) + `box-shadow: var(--ring-border), var(--shadow-card)`. Do **not** use Tailwind `border` utilities on redesigned card surfaces — override shadcn `Card`'s default `border` class.

## Typography

**Project deviation from GSD generic default (intentional, token-locked):** Gemba ships a full locked 8-step type scale in `design-system/tokens/typography.css` with per-size line-heights in px (not a single ratio). The 4 generic template roles are mapped below to the closest Gemba step; the full scale follows since the design system — not the generic default — is canonical.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`--text-body-size`) | 400 regular (`.gemba-body`) | 20px (1.43) |
| Label | 14px | 700 bold (form labels, `.gemba-body-strong`) | 20px |
| Heading (section, H2/H3-equivalent) | 24–28px (`--text-h3-size`/`--text-h2-size`) | 700 bold | 32–36px |
| Display (hero, H1-equivalent) | 40px (`--text-h1-size`) | 700 bold | 48px (1.2) |

Full locked scale (use the matching size for its stated role — do not interpolate new sizes):

| Class / token | Size | Line height | Weight | Use |
|---|---|---|---|---|
| `.gemba-h1` | 40px | 48px | 700 | Home hero headline only |
| `.gemba-h2` | 28px | 36px | 700 | Major section heading |
| `.gemba-h3` | 24px | 32px | 700 | Sub-section heading (e.g. "How it works") |
| `.gemba-h4` | 20px | 28px | 700 | Card/feature title |
| `.gemba-h5` | 16px | 24px | 700 | Smallest heading, nav section labels |
| `.gemba-body` | 14px | 20px | 400 | Default body copy, button labels |
| `.gemba-body-strong` | 14px | 20px | 700 | Form labels, emphasized inline text |
| `.gemba-body-sm` | 12px | 16px | 400 | Hints, captions, subdued micro-copy |
| `.gemba-chip-label` | 10px | 16px | 700 (PT Root UI VF → Public Sans fallback) | Chip/status labels, ALL-CAPS only |

Weights actually used this phase: **Bold 700** (all headings, button labels, chip labels, form labels) and **Regular 400** (body copy, input values, hints). `--fw-medium`(500) and `--fw-semibold`(600) exist in tokens but are not used on the home page — reserve for later phases if a need arises, do not introduce a third weight here.

## Color

Gemba is a low-chroma ink-and-grey system; "accent" is a narrow, deliberately rare informational blue — not the primary CTA color (primary buttons are ink, part of the neutral/dominant family).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surface-page` `#F9FAFB` | Page background (scrolling content area) |
| Secondary (30%) | `--surface-card` `#FFFFFF` | Sidebar, top bar, cards, feature tiles |
| Accent (10%) | `--gemba-accent` `#2066E6` (`--link-color`) | Reserved for: inline hyperlinks/text links, informational icon accents (e.g. an info glyph), the accent Chip variant background tint (`--gemba-accent-subdued` 8%) — never for primary buttons, never as a background fill outside the 8% chip tint |
| Destructive | `--gemba-critical` `#E95E5E` | Destructive actions only — none exist on the home page this phase (no delete/discard flows here); reserved for later phases. If a destructive confirmation is ever needed on this page, use `--gemba-critical` text/icon on `--gemba-critical-subdued` (8%) background |

Additional locked roles used but outside the 60/30/10 slice (ink family, not "accent"):
- `--text-primary` / `--icon-primary` `#283349` (ink-800) — default text, icons, and **primary button fill** (`--button-primary-bg`)
- `--text-subdued` `#697080`, `--text-subtle` `#9499A4` — muted copy, hints, captions
- `--border-default` `#E8EAED` — hairline ring color (see Radii/Shadows above)
- `--gemba-yellow` `#FFDA44` — **brand mark only**, never a UI fill, background, or accent anywhere in product surfaces (hard guardrail)

Accent reserved for: inline links, informational icon glyphs, accent-variant Chip. Never used for: primary/secondary/tertiary button fills, page/card backgrounds, focus rings (focus uses ink `--ring-focus`, not blue).

### Dark mode (DARK-01/DARK-03 — authored this phase, values to be derived not invented)

- Dark surfaces are a **true near-black** OLED-friendly layer (CONTEXT.md D-08): a near-black page background with a step-lighter card surface — not a reuse of the light `#181D27`/`#283349` ink ramp as background, and not a slate/brand-ink derivation.
- Dark accent + signal colors (CONTEXT.md D-09) must be **lightened/desaturated variants** of `#2066E6` (accent), `#20982E` (success), `#CD8C00` (warning), `#E95E5E` (critical) — do not reuse the light hex values verbatim under `.dark`; each must independently meet WCAG AA contrast against the near-black surface.
- Logo swap: **existing mechanism already correct** — `src/components/header.tsx` already swaps `public/logo.svg` (light, `dark:hidden`) / `public/logo-dark.svg` (dark, `dark:block`) via Tailwind `dark:` classes keyed off `next-themes`' `.dark` class. Keep these filenames (do not rename to `gemba-logo-*`, the PROJECT.md note about `gemba-logo.svg` naming does not match what's actually in `public/`) — verify only that the SVG content visually matches `design-system/assets/gemba-logo-full.svg` (mark + "GEMBA" wordmark), do not rebuild the swap logic.

## Component Inventory (resolves CONTEXT.md "Claude's Discretion" items)

### Button ranks → shadcn `Button` variant/size API (COMP-01)
Realized via `cva` variants on the existing `Button` component (`src/components/ui/button.tsx`), retrofit to Gemba tokens rather than replaced:

| Rank | Fill | Text | Shape |
|---|---|---|---|
| Primary | `var(--button-primary-bg)` (#283349 ink) | white | pill `--radius-xl` (24px) default/small; `--radius-sm` (8px) square variants |
| Secondary | `var(--button-emphasized-bg)` (#E8EAED) | `--text-primary` | same shape rules |
| Tertiary | `var(--button-subdued-bg)` (#F3F5F6) | `--text-primary` | same shape rules |
| Ghost | transparent, `--surface-subdued` on hover | `--text-primary` | same shape rules |

Sizes: default = 40px tall, padding `12px 24px`, gap 8, 20px icons; small = 32px tall, padding `12px 16px`, gap 8, 16px icons. Square variants swap `--radius-xl`→`--radius-sm`, same height, icon-only. Labels are verb-first ("Send a file", not "Submit").

### Card recipe (COMP-05)
See Radii & Shadows above — inset-ring + soft-shadow, 16px radius, white surface. Inner sub-cards (e.g. feature icon tile) use `--surface-subdued` at `--radius-md` (12px).

### Chip (COMP-03)
Height 20px, `border-radius: 16px`, padding `3px 10px`, gap 4 (`--space-2`), optional 16px prefix icon. Label: ALL-CAPS, 10px/16px line-height, weight 700, font `.gemba-chip-label` (Public Sans fallback for PT Root UI VF). Background = signal color at 8% tint (`--gemba-{signal}-subdued`), text = full-strength signal color. Variants: neutral / accent / success / warning / critical — home page only needs `neutral` or `accent` (e.g. "OPEN SOURCE" / "END-TO-END ENCRYPTED" badges replacing the current gradient `Badge`).

### Form controls (COMP-02)
Retrofit path (resolves discretion — chosen over lifting raw JSX, to honor the "reuse shadcn" constraint): `Input` and `Switch`/`Toggle` already exist in `src/components/ui/` — reskin in place to Gemba tokens (40px height, `--radius-sm`, `--ring-border`+`--shadow-field`, focus swaps to `--ring-focus`). `Checkbox` and `Radio` do **not** yet exist in `src/components/ui/` — add via `npx shadcn add checkbox radio-group` (shadcn **official** registry, safe by default) then reskin to match `design-system/components/forms/Checkbox.jsx`/`Radio.jsx` token usage. None of these are required by the home page itself (no forms on home) — this recipe is documented now so Phase 2/3 don't re-litigate it, but is not blocking Phase 1 completion.

### Icon wrapper (COMP-04)
Port `Icon.jsx` → `Icon.tsx` (strict-TS convention match) + `icon-data.js` + `Icon.d.ts` into `src/components/` (exact subfolder is an execution detail). All home-page + shell UI icons render through this wrapper (24px, ~1.5–2px stroke, `currentColor`); zero emoji as UI icons anywhere on redesigned surfaces.

### App shell & brand lockup (D-03/D-04, layout paradigm — not previously specified)
- Desktop (≥ md): fixed 240px white sidebar (`--surface-card`) + top bar, scrolling content on `--surface-page`. Active nav item = `--surface-subdued` fill + bold label.
- Mobile (< md): fixed bottom tab bar (Home / Upload / Download) — not a hamburger drawer. Replaces the current `Sheet`-based mobile nav in `header.tsx`.
- Brand lockup: existing "Gemba" wordmark image (`logo.svg`/`logo-dark.svg`, already includes the mark + "GEMBA" text) + a separate "Filesend" label, set in `.gemba-body-sm` (12px, `--text-subdued`), placed immediately to the right of the wordmark, baseline-aligned — matches the current `header.tsx` composition pattern, just reskinned to the subdued token instead of `text-muted-foreground`.

## Copywriting Contract

Home page (PAGE-01) is streamlined toward an app landing per CONTEXT.md D-05 — primary "send a file" action up top, gradient hero and repeated how-it-works/CTA sections dropped or shortened.

| Element | Copy |
|---------|------|
| Primary CTA | **"Send a file"** (verb-first, links to `/upload`) — replaces current "Start Uploading" |
| Secondary CTA | **"Receive a file"** (links to `/download`) — replaces current "Download a File"; verb-first to match Primary |
| Empty state | **Not applicable this phase** — home page has no data list/collection to be empty (anonymous, no accounts, no history). No empty-state copy needed for PAGE-01. |
| Error state | **Not applicable this phase** — home page has no forms or data fetches; a page-level error boundary is out of scope for Phase 1. If one is later needed: heading "Something went wrong", body "Try refreshing the page. If the problem continues, [contact/report] isn't available yet — anonymous product, no support channel." (default, unused this phase) |
| Destructive confirmation | **None on the home page this phase** — no destructive actions exist on PAGE-01. |

Voice per `design-system/DESIGN-SYSTEM.md`: confident, plain, benefit-first; address the user as *you/your*; sentence case for headings/body; ALL-CAPS only for chip/status micro-labels; calm punctuation, no emoji anywhere in UI copy.
