# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Canonical source of truth for every value below:** `design-system/tokens/*.css`, `design-system/APPLY-GUIDE.md`, `design-system/DESIGN-SYSTEM.md`. No color/type/spacing/radius/shadow value is invented outside these files.

**Inheritance model — read this first.** Phase 3 is a per-page application of the Gemba system already locked in `01-UI-SPEC.md` (design foundation) and already precedented on a second page in `02-CONTEXT.md`/`02-PATTERNS.md` (upload page). Every token table, component rank, and guardrail from Phase 1 applies here **unchanged** and is not re-litigated — where this document repeats a Phase 1 table it is for at-a-glance reference only, and the Phase 1 file remains the source of truth on any conflict. This document's real content is the **delta**: the four surfaces that are genuinely new to Phase 3 (error/edge-state cards, the 3-way theme control, the secure-reassurance row, and the DARK-02 completeness bar) plus a page-level migration table for the download state machine.

**Approved deviations carried forward from Phase 1 (still in force, not re-approved here):** the 8-step type scale (overrides the generic ≤4-size ceiling) and the single `--space-1` (2px) token exception. See `01-UI-SPEC.md` "Approved Deviations" for the approval basis. No new deviations are introduced in Phase 3.

## Component Inventory — Phase 3 New Surfaces

Everything not listed here (Button ranks, Card recipe, Chip, Input, Icon wrapper, form-control tokens) is inherited verbatim from `01-UI-SPEC.md` / `02-PATTERNS.md` — reuse those recipes exactly, do not re-derive.

### 1. Error / Edge-State Cards (D-01) — new component pattern

Terminal, non-recoverable failures (invalid link, 404 file-not-found, 410 expired-or-exhausted) render as a dedicated in-page card, replacing the current "toast and silently do nothing" behavior. Structure (reuses the existing `Card`/`CardContent` components — no new component file):

```tsx
<Card>
  <CardContent className="py-12">
    <div className="mx-auto max-w-sm space-y-4 text-center">
      <div className="mx-auto flex size-12 items-center justify-center rounded-[var(--radius-md)] bg-[var(--surface-subdued)]">
        <Icon name="LinkBroken02" size={24} className="text-[var(--icon-subdued)]" />
      </div>
      <div>
        <h3 className="gemba-h4">Invalid share link</h3>
        <p className="gemba-body mt-1 text-[var(--text-subdued)]">
          This link doesn't look right — check that you copied the whole URL, including the part after the #.
        </p>
      </div>
      <Button className="w-full" onClick={handleReset}>
        Try another link
      </Button>
    </div>
  </CardContent>
</Card>
```

This mirrors the existing "done" state's centered `mx-auto max-w-sm space-y-* text-center` layout convention already in the file (lines 419-432 of the current `page.tsx`) — same structural rhythm, different icon/copy/tile-tint per variant. `handleReset` (already defined) is the "Try another link" action — resets to the `input` state.

Three variants (icon tile tint per the Color table above):

| Variant | Trigger | Icon | Headline | Body | Action |
|---|---|---|---|---|---|
| Invalid link | client-side parse failure (bad URL, missing id/key) | `LinkBroken02` | "Invalid share link" | "This link doesn't look right — check that you copied the whole URL, including the part after the #." | "Try another link" |
| File not found | `meta` fetch returns 404 | `SearchRefraction` | "File not found" | "This file may have been removed, or the link may be incorrect." | "Try another link" |
| Expired or exhausted | `meta` fetch returns 410 | `Clock` | "Link expired" | "This file is no longer available — it's expired or reached its download limit." | "Try another link" |

Action button rank: **Primary** (`<Button>`, default variant, `w-full`) — it is the single path forward out of a dead end, so it earns primary emphasis (same logic as the home page's single dominant CTA). This differs from the existing "done" state's low-emphasis `variant="outline"` reset button — do not conflate the two; "done" is a satisfied end state (secondary-rank follow-up action is correct there, unchanged), these three are blocked states (primary-rank recovery action).

These three cards render **in place of** the `input`-state card when triggered (from either the initial link-fetch or the `?id=` deep-link `useEffect`) — exact state representation (new state value vs. a discriminated union) is an execution detail for the planner, not specified here.

### 2. Inline Wrong-Password Field Error (D-01)

401/403 on `handleDownload` keeps the user on the `preview` state (no state transition) and shows an inline message under the password `Input`, instead of the current toast-and-stay-on-preview behavior:

```tsx
<div className="space-y-2">
  <Label htmlFor="password">Password</Label>
  <Input
    id="password"
    type="password"
    aria-invalid={hasPasswordError}
    className={hasPasswordError ? "shadow-[inset_0_0_0_1px_var(--gemba-critical),var(--shadow-field)]" : undefined}
    ...
  />
  {hasPasswordError && (
    <p className="gemba-body-sm flex items-center gap-1 text-[var(--gemba-critical)]">
      <Icon name="AlertCircle" size={16} />
      Incorrect password — try again.
    </p>
  )}
</div>
```

The critical ring swap is derived directly from the existing `--ring-border` pattern (`inset 0 0 0 1px <color>`) with the color substituted for `--gemba-critical` — not a new token, a direct application of the existing inset-ring convention with the signal color. Clear `hasPasswordError` on the next keystroke/change (standard inline-validation UX) so the error doesn't persist through a retry.

### 3. Transient / Network Toasts (D-01) — unchanged

Reserved for genuinely transient blips only: fetch network error (no response at all), presigned-URL-expired retry hint, truncated-download retry. These stay exactly as `sonner` `toast.error(...)` calls — no visual change, `Toaster` (`src/components/ui/sonner.tsx`) is already theme-aware via `useTheme()`. Do not add these to the state-card treatment; only the three D-01 terminal cases and the inline password error move off toasts.

### 4. 3-Way Theme Control (D-02) — replaces `ThemeToggle`

Reuses the existing (currently un-reskinned) `dropdown-menu.tsx` primitives — no new npm install. Trigger keeps the current icon-button affordance (square ghost button, animated Sun/Moon01 crossfade, `aria-label`) from `theme-toggle.tsx`; clicking it now opens a 3-item menu instead of directly toggling:

```tsx
<DropdownMenu>
  <DropdownMenuTrigger asChild>
    <Button variant="ghost" size="icon" aria-label="Change theme">
      {/* existing Sun / Moon01 crossfade icons, unchanged */}
    </Button>
  </DropdownMenuTrigger>
  <DropdownMenuContent align="end">
    <DropdownMenuItem onClick={() => setTheme("light")}>
      <Icon name="Sun" size={16} />
      <span className={theme === "light" ? "gemba-body-strong" : "gemba-body"}>Light</span>
      {theme === "light" && <Icon name="Check" size={16} className="ml-auto" />}
    </DropdownMenuItem>
    <DropdownMenuItem onClick={() => setTheme("dark")}>
      <Icon name="Moon01" size={16} />
      <span className={theme === "dark" ? "gemba-body-strong" : "gemba-body"}>Dark</span>
      {theme === "dark" && <Icon name="Check" size={16} className="ml-auto" />}
    </DropdownMenuItem>
    <DropdownMenuItem onClick={() => setTheme("system")}>
      <Icon name="Monitor01" size={16} />
      <span className={theme === "system" ? "gemba-body-strong" : "gemba-body"}>System</span>
      {theme === "system" && <Icon name="Check" size={16} className="ml-auto" />}
    </DropdownMenuItem>
  </DropdownMenuContent>
</DropdownMenu>
```

`theme` (the user's *selected* preference, not `resolvedTheme`) comes from `useTheme()` — using `theme` (not `resolvedTheme`) is what makes "system" a real, distinguishable, re-selectable third state rather than always resolving to light/dark. `Monitor01` is confirmed present in `icon-data.js` (verified directly, along with `Monitor02`–`05` as fallbacks) — locked, no further verification needed.

**`DropdownMenuContent` reskin (mandatory, since this is the component's first real use):** replace the raw shadcn classes (`border`, `shadow-md`, `bg-popover`) with the Gemba popover recipe: `bg-[var(--surface-card)] shadow-[var(--ring-border),var(--shadow-popover)] rounded-[var(--radius-sm)]` — this is exactly the token Phase 1 pre-provisioned for this purpose ("`--shadow-popover` — Dropdowns/menus only (not needed on home page itself)"). `DropdownMenuItem` should drop its lucide `CheckIcon`/`CircleIcon` imports (replaced by the `Icon` wrapper usage shown above) and its hover state should use `--surface-subdued` (matching the app-shell's active-nav-item convention), not the raw shadcn `focus:bg-accent`.

All three states (light/dark/system) must be reachable and the selection must persist across reloads via `next-themes`' existing localStorage persistence — no new persistence code needed, `next-themes` already handles it.

### 5. Secure Reassurance Row (D-03) — new element inside the preview card

Sits inside the "File Details" card, below the Chips row and above the optional password field:

```tsx
<div className="flex items-start gap-3 rounded-[var(--radius-md)] bg-[var(--gemba-success-subdued)] p-4">
  <Icon name="ShieldTick" size={20} className="mt-0.5 shrink-0 text-[var(--gemba-success)]" />
  <p className="gemba-body-sm text-[var(--text-primary)]">
    End-to-end encrypted — decrypted in your browser; the key never reaches our server.
  </p>
</div>
```

Copy is locked verbatim (from CONTEXT.md D-03) — it is reassurance text describing the existing encryption model, not new behavior, and matches Gemba voice (plain, confident, addresses "your"/"our"). Padding `--space-5` (16px, `p-4`), radius `--radius-md` (12px, inner-sub-card convention — same shape rule as the file-details row and the Phase 2 success icon tile), background `--gemba-success-subdued` (8% tint, already has a lightened dark-mode variant from Phase 1). Only the icon carries full-strength `--gemba-success` — body text stays `--text-primary` ink, which is what keeps this "calm" rather than "a loud green block" per D-03's explicit instruction.

This row is **additional to**, not a replacement for, the "E2E ENCRYPTED" Chip in the Chips row (both exist — see Chip migration table below).
