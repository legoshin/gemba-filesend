<objective>
Fix the known Public Sans production webfont drop: the remote Google Fonts `@import` in
`design-system/tokens/fonts.css` is silently stripped by Turbopack / Lightning CSS in
production builds (flagged in Phases 1–2 and in STATE.md blockers), so the app falls back
to a system font in the deployed build even though `next dev` looks correct. D-04's
DARK-02 checklist explicitly requires Public Sans to render in the deployed build, so this
is the designated place to close it.

Purpose: Typography fidelity is a first-class Gemba design-system constraint; the whole
theme sweep in Plan 04 is meaningless if the primary typeface silently degrades in prod.
Output: Public Sans loaded robustly from `src/app/layout.tsx` so it survives the
production build.
</objective>

## Phase Goal (user story)

**As a** user on the deployed app, **I want to** see the app rendered in Public Sans (its
real typeface) in production, **so that** the Gemba typography is faithful everywhere, not
just in local dev.

| T-03-07 | Tampering | third-party font CDN (CSP interaction) | transfer/note | When Phase 4 adds CSP (SEC-01), `fonts.googleapis.com` (style-src) and `fonts.gstatic.com` (font-src) must be allowlisted; record this so the Phase 4 CSP does not silently break the font. No integrity risk to the encryption boundary. |
| T-03-SC | Tampering (supply chain) | npm installs | accept | The `<link>` approach adds no dependency. If `next/font/google` is chosen it uses the already-present Next.js built-in (no new package). `components.json` unchanged. |
