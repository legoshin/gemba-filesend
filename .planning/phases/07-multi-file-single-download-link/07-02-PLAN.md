<objective>
Rewrite the upload page so a multi-file selection yields ONE share link. The client generates one id and one AES-GCM key, encrypts each file under that key (unique per-file IV) with the existing encryptPacked, uploads each ciphertext part under the one id, finalizes the share with a single POST /api/files/finalize, and shows one link listing the included files.

Purpose: Delivers the user-facing "many files, one link" outcome (MFL-01/MFL-02), building on the finalize + part-upload contract proven in Plan 01.
Output: A single-share upload flow and a one-link result card.
</objective>
