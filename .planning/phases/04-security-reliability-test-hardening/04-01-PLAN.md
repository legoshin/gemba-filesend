## Phase Goal

**As a** person who opens a Gemba Filesend share link, **I want to** have the app's responses hardened with security headers (CSP, HSTS, X-Frame-Options, X-Content-Type-Options), **so that** my session is protected from clickjacking, protocol downgrade, MIME-sniffing, and injected-script abuse — without breaking the fonts, theme, service worker, or the Android app.

<objective>
Ship SEC-01: a pragmatic, ENFORCED (not Report-Only, not nonce-based) Content-Security-Policy plus HSTS, X-Frame-Options, and X-Content-Type-Options on all app responses, set in `next.config.ts` via the Next.js `headers()` API.

This is a self-contained vertical slice: after this plan, inspecting any HTTP response shows the four security headers, and the app (fonts, theme, service worker, blob downloads, Android TWA) keeps working.

Purpose: close the highest-priority header-hardening gap while honoring the Phase 3 T-03-07 carry-forward (the CSP must allowlist the Google Fonts domains or the Public Sans production font silently breaks).
Output: a populated `headers()` block in `next.config.ts`.

Decisions implemented: D-04 (pragmatic enforced CSP in next.config.ts), D-05 (font-CDN + blob-CDN allowlist), D-06 (HSTS + X-Frame-Options DENY + X-Content-Type-Options nosniff + frame-ancestors none). D-07 (nonce/strict-dynamic CSP) is explicitly OUT of scope for this phase and must NOT be introduced.
</objective>

    Strict-Transport-Security: `max-age=63072000; includeSubDomains; preload` (D-06 HSTS).
    X-Frame-Options: `DENY` (D-06).
    X-Content-Type-Options: `nosniff` (D-06).

    Keep the CSP as a readable array of directive strings joined with `"; "` so future edits stay legible. Do not add Report-Only, a nonce, middleware, or per-request logic — those are D-07 / deferred. Touch only next.config.ts.
