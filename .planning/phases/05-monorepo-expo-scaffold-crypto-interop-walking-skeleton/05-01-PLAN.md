<objective>
Restructure the repository into an npm-workspaces monorepo and relocate the existing Next.js app from the repo root into `apps/web`, without regressing its build, its Phase 4 test suite, or its Phase 4 security headers. This is the foundation every later plan in this phase builds on: the shared crypto package (05-02) and the Expo app (05-03) both require the workspace root to exist first.

Per D-06 the tooling stays npm (keep `package-lock.json`; no pnpm/Turborepo). Per D-07 the move requires a one-time Vercel Root Directory change, treated here as a human-gated deploy verification.

Purpose: Establish `apps/web` + workspace root so crypto/meta can be single-sourced in `packages/*` and consumed by both web and native.
Output: Workspace root `package.json`, the Next app relocated under `apps/web`, a green `apps/web` build + test run, and a recorded Vercel Root Directory action.
</objective>

<phase_goal>
## Phase Goal

**As a** Gemba Filesend maintainer, **I want to** stand up a monorepo whose single-sourced crypto package encrypts and decrypts byte-for-byte identically on web and native, **so that** I can build the native uploader/downloader on a trusted crypto foundation without risking web↔native incompatibility.

This plan delivers the first slice: after it completes, the maintainer has a working workspace root with the web app running unchanged from its new `apps/web` home — a real, verifiable end state, not scaffolding-in-waiting.
</phase_goal>
