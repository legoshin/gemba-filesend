**As a** person sharing files, **I want** the upload flow — dropzone, share options, and the generated share link — redesigned to the Gemba design system and theme-aware in light and dark, **so that** sharing a file feels consistent, polished, and trustworthy across the whole app.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → `/api/files` (upload) | Encrypted blob + metadata header cross to the server. **Unchanged this phase** — no edit to the upload call, headers, or payload. |
| client → `/api/storage-mode` | Read-only mode probe in `useEffect`. Unchanged. |
| encryption key → URL fragment | The decryption key is placed only in the share-link fragment (`#${keyB64}`), never sent to the server. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-A | Tampering | share-link construction in `uploadOneFile` (`${origin}/download?...#${keyB64}`) | accept (**must-not-regress**) | Reskin edits only JSX/className/imports; `uploadOneFile`, `uploadDirect`, and the return string are preserved byte-for-byte — the key stays in the URL fragment and is never added to any request body/header. |
| T-02-02-B | Information Disclosure | password → hash/salt path (`sha256Hex(password + salt)`, `randomSaltBase64`) | accept (**must-not-regress**) | Password handling lives in `uploadOneFile`/`handleUpload`, which are untouched; the reskin never reads or relocates the password beyond the existing `<Input>` binding. |
| T-02-02-C | Information Disclosure | readonly share-link `<Input>` in the done state | accept | The link (including the fragment) was already rendered for the user to copy; styling-only change, no new exposure. |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package installs — `Icon`/`Chip`/`Button`/`Card`/`Input`/`Switch` already shipped in Phase 1. Any future component add is shadcn OFFICIAL only per Phase 1 UI-SPEC Registry Safety. |

**Encryption boundary:** Client-side-encryption model is preserved. The one invariant to protect (**must-not-regress**): the reskin must not alter where the decryption key is placed (URL fragment only) or how password hashing/salt is handled — both live in untouched functions.
