<objective>
Make a distributable, notarized DMG reachable with one command on a machine that has the
Developer ID certificate, while keeping the project buildable on machines that do not.

Purpose: closes the last spec phase (signing + distribution) now that an Apple Developer account
is confirmed. The certificate itself is NOT on this Mac yet, so the path past identity discovery
is configured and reviewed but not executed.
Output: signing config, icon, and a packaging script that either produces a notarized DMG or
stops with an actionable message.
</objective>

## Tasks

1. **Signing configuration** — `macos/Configs/Signing.xcconfig`, referenced as the project's base
   configuration. Ad-hoc (`-`) by default, hardened runtime on, manual style. Distribution
   identity deliberately not hardcoded; the script overrides on the command line.
2. **Notarization hygiene in the project** — `CODE_SIGN_INJECT_BASE_ENTITLEMENTS = NO` for Release
   in the project and both targets.
3. **App icon** — `scripts/make-icon.sh` builds `AppIcon.icns` from the brand mark;
   `CFBundleIconFile` declared and the .icns shipped as an app resource.
4. **Packaging** — `scripts/package-dmg.sh`: run the interop tests, archive and export with the
   discovered identity, verify signature/hardened-runtime/entitlements/nested extension, build and
   sign the DMG, notarize with whichever credentials are present, staple, and check with `spctl`.

## Status at time of writing

Tasks 1-4 complete and self-verified as far as the absent certificate allows:
- Ad-hoc Release build: hardened runtime on, entitlements now sandbox + network + user-selected

## Decision, 2026-09-17: local signing only

The user chose to **sign locally, not distribute** — no Developer ID certificate, no
notarization, no App Store. The certificate was never installed (`security find-identity -v -p
codesigning` → 0 identities, no Apple ID signed into Xcode), and that is now the intended state
rather than a blocker.

What this means in practice:
- Ad-hoc signing IS the shipping configuration for this app. It is a real signature, with the
  hardened runtime on and the sandbox enforced — it just carries no team identity.
- The app was installed to `/Applications`, launched, and the Share Extension registered and
  enabled (`pluginkit -m -p com.apple.share-services` shows `+ uk.gemba.filesend.mac.ShareExtension`).
- The build has no quarantine attribute because it was built on this machine, so Gatekeeper
  never challenges it here.
- **The one consequence:** a copy handed to anyone else — AirDrop, a download, a shared drive —
  arrives quarantined and Gatekeeper will refuse to open it. Local use only.

`Configs/Signing.xcconfig` and `scripts/package-dmg.sh` stay in the repo unused. They are the
whole distribution path, ready if that decision changes; nothing in them needs editing beyond
installing a certificate. Everything from `xcodebuild archive` onward in that script remains
untested against a real identity.

Tasks 1-3 (signing config, notarization hygiene, icon) were kept regardless of the decision:
stripping `get-task-allow` from Release and enabling the hardened runtime are correct for a
local build too, and the icon is visible in the Dock either way.
