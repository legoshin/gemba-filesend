<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: Live per-recipient notify + coupling/chip UX + platform-parity sign-off</name>
  <what-built>
    Upload-time recipient notification: a Notify Recipient toggle (auto-enabling Verify), a single
    shared chip-input recipient list, and a /api/notify endpoint that sends one Mailgun email per
    recipient containing the upload's download link(s). Works for encrypted + unencrypted uploads.
  </what-built>
  <how-to-verify>
    On the deployed preview (with Mailgun env set):
    1. Coupling: toggle Notify ON → Verify turns ON automatically. Toggle Verify OFF while Notify
       stays ON (must be allowed). Toggle Notify OFF → Verify stays as last set.
    2. Shared list: the recipient field appears when either toggle is on; there is exactly one
       recipient field. Type an email + Enter → it becomes a removable [x] chip. Type an invalid
       string + Enter → inline rejection, no chip added. Remove a chip via its [x].
    3. Multi-recipient send: add 2+ recipient chips, enable Notify, upload a file. Confirm EACH
       recipient inbox receives its OWN separate email (recipients must NOT see each other in To/CC).
    4. Working link — encrypted: open the emailed link on a fresh browser → the file downloads and
       decrypts (key rode in the #fragment).
    5. Working link — unencrypted fallback: force the unencrypted path, upload, open the emailed
       link → the file downloads (no fragment).
    6. Multi-file: upload 2+ files with Notify on → each recipient's email lists all produced links.
    7. Failure is non-blocking: confirm that if notify send fails, a toast appears but the upload
       result (share links) still renders and is copyable.
    8. Platform parity: repeat a representative send on the installed PWA and the Android TWA build;
       confirm the toggle/chip UI renders and the emailed link opens on each.
  </how-to-verify>
  <resume-signal>Type "approved" to close the phase, or list defects to feed a --gaps closure plan.</resume-signal>
</task>
