<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser ↔ page render | Motion runs entirely client-side; entrance/scroll motion is presentation only and reads no untrusted input. |
| motion wrappers ↔ crypto/storage core | Presentation wrappers must not reach into the client-side-encryption path (key never leaves the client). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Tampering | src/lib/crypto.ts, storage.ts, multi-file.ts | high | mitigate | Every task `<verify>` runs a git-diff-guard asserting zero diff to crypto.ts/storage.ts/server-storage.ts/blob-storage.ts/multi-file.ts — motion changes cannot touch the encryption boundary. |
| T-11-02 | Tampering | design-system/tokens/ (colour/type) | medium | mitigate | git-diff-guard asserts zero diff to design-system/tokens/; the scroll bar and entrance reuse existing tokens/presets only. |
| T-11-03 | Denial of Service | ScrollProgress useScroll/useSpring scroll handler | low | accept | Passive rAF-driven MotionValue with no per-scroll React state churn; reduced-motion drops the spring. Not a server-facing surface. |
