  <action>
Wire one path from the untrusted URL params through to hidden chrome + overridden background.

Create src/components/embed-provider.tsx as a client component ("use client"). It defines:
- An `EmbedState` interface with two fields: `isEmbed: boolean` and `backgroundColor: string | null`.
- A module `DEFAULT: EmbedState` equal to isEmbed false and backgroundColor null.
- A React context created with `createContext<EmbedState>(DEFAULT)` (do not export the context itself).
- An exported `useEmbed(): EmbedState` hook that returns `useContext` of that context.
- An exported PURE function `normalizeEmbedColor(raw: string | null | undefined): string | null`. Behavior: return null when raw is falsy; return null when `raw` fails the strict test `/^#?[0-9a-fA-F]{3,8}$/`; otherwise return raw when it already begins with a hash character, else return raw with a single leading hash prepended. SECURITY: the only value ever derived from user input is the validated hex body; the leading hash is a literal — the raw param is NEVER concatenated into a CSS declaration or style string, it is only ever returned for use as an inline style object value in the consumers.
- An inner `EmbedReader({ children })` client component that calls `useSearchParams()` from next/navigation, computes `isEmbed` as (`params.get("mode") === "embed"`) and `backgroundColor` as `normalizeEmbedColor(params.get("color"))`, and renders the context Provider with that value wrapping children.
- An exported `EmbedProvider({ children })` that returns a `<Suspense>` (imported from react) whose `fallback` renders the context Provider with the DEFAULT value wrapping the same children, and whose child is `<EmbedReader>` wrapping children. The DEFAULT-value fallback is what keeps server-prerendered pages (including the static home page) rendering their real content; the real params are read on the client after hydration. This Suspense boundary is what lets `next build` prerender without bailing out on useSearchParams.

Edit src/app/layout.tsx: import `EmbedProvider` from "@/components/embed-provider" and wrap the existing `<AppShell>{children}</AppShell>` with `<EmbedProvider>...</EmbedProvider>` (EmbedProvider outside AppShell, inside ThemeProvider). Change nothing else — keep the font links, Toaster, and sw-register Script exactly as-is.

Inline style takes precedence over the bg-[var(--surface-page)] class, so a valid color wins and an absent color falls back to the themed token. Apply the same conditional inline style to the outer flex container div as well so the color fills the viewport when chrome is hidden.
Do not introduce any new component, do not alter the non-embed markup, class strings, or the ThemeToggle wiring.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query → client render | `mode` and `color` params on /upload are attacker-controllable (the embed URL is supplied by the framing app / user). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------------|-----------------|
| T-embed-01 | Tampering/Injection | `color` param → background style | high | mitigate | Validate against strict `^#?[0-9a-fA-F]{3,8}$` in `normalizeEmbedColor`; apply ONLY as an inline style object value (`style={{ backgroundColor }}`), never string-interpolated into a CSS/style declaration; ignore (return null → no override) on any mismatch. Note: 5/7-digit hex passes the length range but is simply ignored by the browser as an invalid color value in a style object — no injection surface. |
| T-embed-02 | Tampering (UI redress) | `mode=embed` hides chrome | low | accept | Embed mode only omits nav chrome + heading; it exposes no new capability and does not touch the client-side-encryption boundary. Framing/clickjacking remains governed by the existing (unchanged) CSP/framing headers in next.config.ts — out of scope for this change. |
| T-embed-03 | Information disclosure | key never reaches server | low | accept | No change to crypto flow: the key stays in the URL fragment and is encrypted client-side; embed mode reads only `mode`/`color` from the query string and never the fragment. |
</threat_model>
